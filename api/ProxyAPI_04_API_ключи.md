# ProxyAPI: API-ключи и ошибки

Источники (сверено 24.11.2026, редакция страниц от 02.09.2026):
- https://proxyapi.ru/docs/api-keys
- https://proxyapi.ru/docs/errors

## Ключ

- Ключ API - единственный способ авторизации в ProxyAPI. Одного ключа хватает на весь каталог моделей (OpenAI, Claude, Gemini, DeepSeek, Qwen и др.).
- Создание: раздел **Ключи API**, кнопка «Создать новый ключ API». Ключу можно дать имя, оно видно только в кабинете.
- Ключ начинается с `sk-` и показывается целиком **один раз**. В списке он виден частично.
- По умолчанию можно создать до 10 ключей. Удобно заводить отдельный ключ на каждое приложение.
- Ключ не хранят в коде и не публикуют в репозиториях. Утёк - аннулируйте и создайте новый.

## Передача ключа

Основной способ, работает везде:

```
Authorization: Bearer <КЛЮЧ>
```

Другие способы (`X-API-Key`, `x-goog-api-key`, параметр `?key=`) нужны только официальным библиотекам Anthropic и Google. Самому их выбирать незачем.

## Ограничения ключа

Настраиваются в разделе «Ключи API» при редактировании ключа:

| Настройка | Что даёт |
|---|---|
| Доступные модели | Список разрешённых моделей. Пусто - доступны все |
| Бюджет | Предел расходов по ключу: разовый или ежемесячный. 0 - без ограничения. Ежемесячный бюджет сравнивается с расходом **всего аккаунта** за месяц |
| Белый список IP | Запросы принимаются только с указанных IPv4-адресов или подсетей (CIDR). IPv6 не поддерживается |
| Разрешения | Доступ к служебным методам, например к запросу баланса |

Расход по ключу начинает считаться только после того, как задан бюджет.

## Аннулирование

Ненужный или скомпрометированный ключ аннулируется в списке ключей. Действие необратимо: запросы с этим ключом перестают работать, вместо него создаётся новый.

## Формат ошибок

- Проверки ProxyAPI (ключ, баланс, доступ) отвечают полем `detail`: `{"detail": "Insufficient balance to run this request."}`
- Ошибки конечного сервиса приходят в формате эндпоинта. Для формата OpenAI: `{"error": {"message": "...", "type": "...", "param": null, "code": null}}`

Так можно понять, кто вернул ошибку: `detail` - ProxyAPI, `error` - сама модель.

## Коды ошибок

| Код | Сообщение / причина | Что делать |
|---|---|---|
| 400 | Неверный JSON, неизвестное поле, недопустимое значение | Проверить тело запроса |
| 401 | `Invalid API Key` - ключ не передан или не существует. Также: не определён IP или аккаунт заблокирован (`User is banned`) | Проверить ключ и базовый адрес `https://api.proxyapi.ru/v1` |
| 402 | `Insufficient balance to run this request.` - мало денег на балансе | Пополнить баланс |
| 402 | `API Key budget exceeded.` / `Monthly budget exceeded.` - исчерпан бюджет ключа или месяца | Поднять бюджет |
| 403 | `IP address not allowed` / `Model not allowed` - IP или модель вне разрешённых для ключа | Проверить настройки ключа |
| 404 | Модель или файл с таким ID не найдены | Сверить ID с каталогом |
| 429 | `Too many requests` - превышен лимит частоты запросов | Повторить позже |
| 502 | Конечный сервис недоступен | Повторить запрос |
| 504 | Истекло время ожидания ответа | Повторить запрос |

**402 при непустом балансе.** Либо исчерпан бюджет ключа или месяца, либо денег не хватает на предварительную оценку: перед запросом стоимость считается с запасом на самый длинный возможный ответ. Как устроена оценка и как её уменьшить: https://proxyapi.ru/docs/cost-of-request

**429** бывает по нескольким причинам с одинаковым текстом: лимит запросов, защита от подбора ключей, много ошибочных запросов подряд, ограничение со стороны поставщика.
