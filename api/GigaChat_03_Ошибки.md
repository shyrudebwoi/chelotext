# GigaChat API: ошибки и что с ними делать

Источники (сверено 24.11.2026):
- https://developers.sber.ru/docs/ru/gigachat/api/errors-description
- https://developers.sber.ru/docs/ru/gigachat/certificates

Ошибка приходит как HTTP-код и JSON. При получении токена тело обычно вида `{"code": 5, "message": "..."}`, в остальных запросах `{"status": 401, "message": "..."}`. Точная причина - в поле `message`.

## Ошибка сертификата (до любого HTTP-кода)

| Текст | Причина | Решение |
|---|---|---|
| `[SSL: CERTIFICATE_VERIFY_FAILED] certificate verify failed: self-signed certificate in certificate chain` | Не установлен корневой сертификат НУЦ Минцифры | Добавить сертификат, см. `GigaChat_01_Авторизация.md`. Не отключать проверку (`verify=False`) |

## 400 - ошибка в параметрах запроса

| Сообщение | Причина | Решение |
|---|---|---|
| (запрос токена без `RqUID`) | Нет заголовка `RqUID` или он не в формате uuid4 | Передать `RqUID: str(uuid.uuid4())` |
| `scope is empty` (code 5) | В теле запроса токена нет `scope` | Передать `scope=GIGACHAT_API_PERS` (для физлиц) |
| `scope from db not fully includes consumed scope` (code 7) | Ключ авторизации не соответствует версии API в `scope` | Указать версию API, которая отображается в личном кабинете |
| `scope data format invalid` (code 1) | Опечатка в значении `scope` | Проверить значение `scope` |
| `{"status": 400, "message": "..."}` в других запросах | В `message` указан параметр с ошибкой | Исправить этот параметр |

## 401 - ошибка авторизации

| Сообщение | Причина | Решение |
|---|---|---|
| `Can't decode 'Authorization' header` (code 4) | Опечатка в ключе авторизации или лишние символы | Скопировать ключ из кабинета заново. В заголовке: `Basic <ключ>` |
| `credentials doesn't match db data` (code 6) | Ключ не соответствует версии API в `scope` | Перевыпустить ключ в личном кабинете |
| `Unauthorized` (в запросах к модели) | Пустой заголовок `Authorization` или токен старше 30 минут | Получить новый токен. Обновлять токен до истечения `expires_at` |

## 402 - требуется оплата

| Сообщение | Причина | Решение |
|---|---|---|
| `Payment Required` | Закончились токены модели, к которой идёт запрос | Проверить лимит этой модели в кабинете. Перейти на модель, где токены есть, или пополнить баланс |

## 403 - нет доступа

| Сообщение | Причина | Решение |
|---|---|---|
| `Unauthorized` при запросах на `https://api.giga.chat/` | Нет заголовка `User-Agent` | Передать `User-Agent` с любым значением |
| `Permission denied` при `GET /balance` | При оплате по факту (pay-as-you-go) предоплаченного остатка нет | Не вызывать `/balance` при такой схеме оплаты |

## 404 - не найдено

Например, ошибка в названии модели. Сверить `model` со списком `GET /v1/models`.

## 413 - слишком большой запрос

| Сообщение | Причина | Решение |
|---|---|---|
| `Payload too large` | Промпт больше контекста модели | Сократить текст или разбить на части. Посчитать токены можно запросом `POST /tokens/count` |

## 422 - ошибка валидации

| Сообщение | Причина | Решение |
|---|---|---|
| `Invalid params: system message must be the first message` | Несколько `system`-сообщений или `system` не первым | Оставить одно `system`-сообщение в начале `messages` |
| `Unprocessable Entity for url: <...>/chat/completions` | Файл из `attachments` больше контекста модели | Разделить или сократить текст |
| `Requested model does not support functions` | Модель не поддерживает пользовательские функции | Убрать функции из запроса или сменить модель |

## 429 - слишком много запросов

| Сообщение | Причина | Решение |
|---|---|---|
| `Too Many Requests` | Одновременных запросов больше, чем разрешено. Физлицам доступен 1 поток, ИП и юрлицам - 10 | Отправлять запросы по очереди, повторять после паузы |

## 500 - внутренняя ошибка сервиса

`Internal Server Error`. Повторить позже. Если повторяется - писать в поддержку: gigachat@sberbank.ru.

## Как просить агента разобрать ошибку

Передавайте агенту точный текст ошибки **без ключей и токенов** и укажите провайдера: «Используемый провайдер - GigaChat». Не разрешайте агенту чинить ошибку сменой провайдера, случайной заменой ключей или отключением проверки сертификатов.
