# Безопасное добавление API-ключей

Правила для ИИ-агента и для человека. Действуют для GigaChat, ProxyAPI и любых других ключей.

## Обязательные правила для агента

1. **Не вписывать ключ в код**, даже если пользователь просит «просто вставь, чтобы заработало».
2. **Не просить прислать ключ в чат** и не повторять его, если пользователь прислал сам.
3. **Не выводить ключ и токены** в логи, print, сообщения об ошибках, ответы API. Если нужно показать, что ключ загружен, показывать только факт: `GIGACHAT_CRED: задан`.
4. **Ключ живёт только на сервере.** Браузер (HTML, JavaScript) ключ не получает. Схема: форма в браузере -> сервер приложения -> API нейросети -> сервер -> результат на экране.
5. **Не отключать проверку сертификатов** (`verify=False`) ради устранения ошибки.
6. Не подменять выбранного провайдера другим без согласия пользователя.

## Где хранить ключи: файл .env

В корне проекта создаётся файл `.env`. Пользователь сам вписывает в него значения:

```
GIGACHAT_CRED=
GIGACHAT_SCOPE=GIGACHAT_API_PERS
GIGACHAT_MODEL=GigaChat-2
PROXYAPI_API_KEY=
```

Значения пишутся без кавычек и пробелов вокруг `=`.

Код читает их через `python-dotenv`:

```python
import os

from dotenv import load_dotenv  # pip install python-dotenv

load_dotenv()

GIGACHAT_CRED = os.getenv("GIGACHAT_CRED")
if not GIGACHAT_CRED:
    raise RuntimeError("Не задан GIGACHAT_CRED в файле .env")
```

## .gitignore

Файл `.env` никогда не попадает в репозиторий и архив для сдачи. В `.gitignore`:

```
.env
venv/
.venv/
__pycache__/
```

Вместо `.env` в проект кладут `.env.example` с теми же переменными, но **пустыми значениями**. По нему другой человек понимает, какие ключи нужны.

## Порядок действий для человека

1. Получить ключ в личном кабинете сервиса (GigaChat: Studio -> проект GigaChat API -> Настройки API -> Получить ключ. ProxyAPI: раздел «Ключи API»).
2. Сразу сохранить ключ: оба сервиса показывают его целиком один раз.
3. Открыть `.env` в редакторе, вставить значение после `=` вручную, сохранить файл.
4. Перезапустить приложение: переменные читаются при старте.
5. Проверить работу на учебном тексте без личных данных.

## На сервере

`.env` на сервер переносится вручную (или ключи задаются в настройках переменных окружения хостинга). В git и публичные архивы ключи не попадают.

## Если ключ утёк

Ключ попал в код, на скриншот, в чат, в репозиторий:

- **GigaChat**: в личном кабинете нажать «Получить новый ключ». Сервис спросит, сколько ещё будет действовать старый ключ (максимум 250 минут): при утечке ставьте минимальное время.
- **ProxyAPI**: аннулировать ключ в разделе «Ключи API» и создать новый.

Удалить ключ из кода недостаточно: он остаётся в истории git и в копиях. Нужно выпустить новый.

## Скриншоты и сдача работ

Перед отправкой скриншота или архива закрыть или удалить ключи, токены, Client Secret. В архив для проверки не класть `.env`, `venv`, базу пользователей, логи.
