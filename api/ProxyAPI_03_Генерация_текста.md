# ProxyAPI: генерация текста

Источник (сверено 24.11.2026, редакция страницы от 02.09.2026):
- https://proxyapi.ru/docs/text-generation

Эндпоинт: **POST** `https://api.proxyapi.ru/v1/chat/completions`. Через него доступна любая текстовая модель каталога, независимо от поставщика.

## Сообщения и роли

Диалог передаётся списком `messages`:

| Роль | Кто говорит | Зачем |
|---|---|---|
| `system` | Инструкция для модели | Правила: тон, язык, формат ответа, ограничения. Ставится первым |
| `user` | Человек | Вопрос или задание |
| `assistant` | Модель | Её предыдущие ответы |

Системное сообщение необязательно, но управляет поведением модели надёжнее, чем просьба внутри сообщения пользователя.

## Модель не помнит переписку

Каждый запрос обрабатывается отдельно. Чтобы продолжить диалог, отправляйте всю историю заново, вместе с ответами модели в роли `assistant`. Длина истории ограничена контекстом модели: старые сообщения обрезают или заменяют кратким пересказом.

## Параметры

| Параметр | Что делает |
|---|---|
| `model` | ID модели, например `openai/gpt-5-mini` |
| `messages` | История диалога |
| `temperature` | Разброс ответов. Ближе к 0 - предсказуемо, выше - свободнее |
| `top_p` | Альтернатива `temperature`. Меняйте что-то одно |
| `max_tokens` | Верхний предел длины ответа в токенах |
| `stop` | Строка или список строк, на которых генерация обрывается |

Набор поддерживаемых параметров у моделей разный. Незнакомый параметр конечный сервис либо игнорирует, либо отвечает ошибкой 400.

## Пример (Python)

```python
import os

from openai import OpenAI

client = OpenAI(
    api_key=os.environ["PROXYAPI_API_KEY"],
    base_url="https://api.proxyapi.ru/v1",
)

response = client.chat.completions.create(
    model="openai/gpt-5-mini",
    messages=[
        {"role": "system", "content": "Ты редактор. Отвечай кратко."},
        {"role": "user", "content": "Сократи: длинное предложение о погоде."},
    ],
    temperature=0.3,
    max_tokens=200,
)

print(response.choices[0].message.content)
print(response.usage)
```

## Ответ

```json
{
  "choices": [
    {
      "index": 0,
      "message": {"role": "assistant", "content": "Завтра тепло."},
      "finish_reason": "stop"
    }
  ],
  "usage": {
    "prompt_tokens": 24,
    "completion_tokens": 3,
    "total_tokens": 27
  }
}
```

Текст ответа: `choices[0].message.content`.

`finish_reason`:

| Значение | Что произошло |
|---|---|
| `stop` | Ответ завершён полностью |
| `length` | Упёрлись в `max_tokens` или предел модели, ответ оборван |
| `tool_calls` | Модель просит вызвать функцию |
| `content_filter` | Ответ заблокирован фильтром конечного сервиса |

`usage` - расход токенов: `prompt_tokens` (вход вместе со всей историей), `completion_tokens` (ответ), `total_tokens`. По этим числам считается стоимость запроса.

## Частые вопросы

- **Ответ обрывается на полуслове.** В `finish_reason` будет `length`. Увеличьте `max_tokens` или попросите модель отвечать короче.
- **Одинаково ли работают модели разных поставщиков?** Структура запроса и ответа одна. Различаются набор поддерживаемых параметров и реакция на системное сообщение.
