# ТЕХНИЧЕСКОЕ ЗАДАНИЕ — веб-приложение «Челотекст»

> Версия: 1.0 · Дата: 23.11.2026
> Контекст и история решений — в [context.md](./context.md). Дизайн-код — в [design.md](./design.md).

---

## 1. Цель продукта
«Челотекст» — веб-сервис, который меняет **подачу** текста, делая его легче для чтения, но **сохраняет смысл, факты, имена, числа и цитаты**. Продукт не сокращает содержание, а переформатирует и упрощает язык.

**Ценность:** массовый читатель длинных текстов (новости, лонгриды, документы, посты) получает тот же по объёму информации текст, но читаемый быстрее и без усталости.

## 2. Аудитория и проблема
- **Аудитория:** массовые читатели (не узкие специалисты). Язык — русский (MVP); многоязычность — в отдалённом бэклоге.
- **Проблема (комбинированная):**
  - «плотный» текст — огромные абзацы, теряется строка, устают глаза;
  - сложный язык — канцеляризмы, длинные предложения, повторы;
  - нет визуальной структуры — заголовки теряются, нельзя «сканировать».

## 3. Пользовательские сценарии
**Приоритет MVP — ручной копипаст.**
1. **(MVP)** Пользователь вставляет текст из буфера в поле → настраивает режимы → получает переформатированный текст → правит в редакторе → копирует/скачивает.
2. **(Очередь)** Вставляет ссылку на статью/пост → сервис извлекает текст → обрабатывает → результат в том же пайплайне.
3. **(Очередь)** Загружает файл-вложение (DOCX/PDF/TXT/EPUB) → обработка длинного документа.

## 4. Функциональные требования

### 4.1 Режимы обработки (гибрид, переключаются независимо)
- **R1 Визуальное форматирование:** разбивка на абзацы, крупные заголовки, интервалы, выравнивание.
- **R2 Лингвистическое упрощение:** замена канцеляризмов, укорочение предложений, устранение повторов.
- **R3 Структурирование:** автовыделение заголовков, списков, ключевых мыслей.
- Пользователь включает/выключает каждый режим независимо.

#### 4.1.1 Сохранение структуры PDF при извлечении
При извлечении текста из PDF **максимально сохраняем исходную структуру**:
- **Таблицы** → Markdown-таблицы (для дальнейшего экспорта в MD/PDF/HTML).
- **Многоколоночная вёрстка** → корректная склейка колонок в логической последовательности чтения.
- **Колонтитулы, номера страниц, служебные пометки** → вырезаются как технический мусор.
- **Сноски** → собираются в отдельный список (в конце блока/документа) с сохранением привязки по номеру.
- Сохранённая структура передаётся в режимы R1–R3 и используется при экспорте (Markdown-разметка сохраняется в MD, отображается в PDF/HTML).

### 4.2 Ползунок глубины
`Лёгкая стилистическая правка ←——→ Глубокое упрощение и переработка`.
- 3–5 дискретных уровней (например, 1…5).
- Уровень определяет агрессивность LLM-промпта и порог срабатывания правил.

### 4.3 Вход
- Вставка текста в поле; **лимит 100 000 знаков** (валидация на клиенте и сервере).
- (Очередь) URL-статья; (Очередь) файлы DOCX/PDF/TXT/EPUB.

#### 4.3.1 PDF: гибридный подход
Приложение поддерживает PDF обоих типов и **само определяет** способ извлечения:
- **PDF с текстовым слоем** → извлечение текста напрямую (без OCR).
- **Сканированный PDF (без текстового слоя)** → распознавание через **Tesseract OCR**.
- Смешанные документы: обработка постранично (слой — извлекаем, скан — OCR).

**Языки OCR:** `rus` + `eng` (оба языка могут встречаться в одном файле; список языков расширяем конфигурацией).

**Лимиты PDF:** **100 000 знаков** извлечённого текста **ИЛИ 50 страниц** (что наступит раньше). Лимит по знакам общий с текстовым входом. Валидация на клиенте и сервере.

**Предупреждение OCR:** при распознавании скана показываем пользователю сообщение
> «Текст распознан автоматически, возможны ошибки распознавания. Результат открыт в редакторе для ручной доводки»

и сразу открываем результат во **встроенном редакторе** (см. 4.4). Файл помечается как «получен из OCR» в истории.

### 4.4 Выход
- Отображение результата в браузере.
- **Параллельный вид:** слева оригинал, справа результат, **подсветка различий (diff)**.
- **Встроенный редактор** уже «очеловеченного» текста (правки пользователя сохраняются).
- **Скачивание:** как минимум **TXT, PDF, Markdown** (обязательно); DOCX и HTML — по возможности. Пользователь выбирает формат.
- Копирование в буфер обмена (форматированный plain text).

### 4.5 Аккаунты и история
- Регистрация/вход.
- **История обработанных текстов** (вход → настройки → результат) с возможностью вернуться и редактировать.
- **Согласие на обработку ПДн** — обязательный шаг (см. раздел 8).

### 4.6 Предпроверка контента
- До обработки — фильтр: отклонить незаконный контент и чужие авторские тексты целиком; **разрешить научные статьи**.
- Механизм: стоп-списки/классификатор + правила; при срабатывании — понятное сообщение и блокировка обработки.

## 5. Нефункциональные требования
- **Скорость:** типичные тексты — синхронно до ~60 сек с индикатором прогресса и кнопкой отмены; длинные (десятки тыс. знаков) — **асинхронная очередь** задач со статусом и уведомлением о готовности.
- **Скан-PDF — всегда асинхронно:** распознавание через Tesseract медленнее, поэтому загрузка скан-PDF ставится в очередь независимо от объёма.
  - Жизненный цикл задачи: `загружен → извлечение/OCR → обработка (R1–R3) → готово`; статусы видны на экране задачи (см. 7.6).
  - По завершении — уведомление о готовности и **автооткрытие результата во встроенном редакторе** с предупреждением OCR (см. 4.3.1).
  - Пользователь может отменить задачу на любой стадии; отмена останавливает и OCR.
- **Бюджет/инфраструктура:** «бесплатно или очень дёшево» → приоритет бесплатных тарифов LLM-API, открытых/самохостимых моделей и **гибрида «правила + модель»** (правила снимают простую работу, LLM — только сложное упрощение). Нужен слой-абстракция провайдера LLM (заменяемый). OCR — самохостимый Tesseract (бесплатно).
- **Офлайн:** не в MVP (отложено).
- **Доступность (a11y):** семантическая разметка, контраст, поддержка скринридеров, управление с клавиатуры — важно, т.к. часть аудитории — люди с трудностями чтения.
- **Масштабируемость:** заложить асинхронную обработку под рост нагрузки.

## 6. Данные (логическая модель)
- **User:** id, email, статус согласия ПДн, дата регистрации.
- **Consent:** факт и время согласия, версия политики.
- **Document:** id, user_id, источник (paste/url/file), исходный текст (срок хранения), мета (объём, язык).
- **Job:** id, document_id, настройки (режимы R1–R3, уровень ползунка), статус (queued/processing/done/failed/cancelled), прогресс, результат-текст, временные метки.
- **Edit:** правки пользователя в результате (версии/ревизии).
- **Export:** журнал скачиваний (формат, время).
- Хранение исходников и результатов — с учётом политики удаления (см. раздел 8).

## 7. Структура и экраны
1. **Лендинг** — ценность + кнопка «Начать».
2. **Онбординг + согласие ПДн** — чекбокс согласия, ссылки на политику/оферту.
3. **Вход/Регистрация.**
4. **Главный рабочий экран (Editor):**
   - зона вставки текста + счётчик знаков + валидация лимита;
   - панель настроек (переключатели R1–R3, ползунок глубины);
   - кнопка «Обработать»;
   - **параллельный вид** (оригинал ↔ результат с diff);
   - **редактор результата**;
   - панель экспорта (копировать, скачать: TXT/PDF/MD + DOCX/HTML).
5. **Экран истории** — список документов/задач, поиск, открытие.
6. **Экран задачи (асинхронной)** — прогресс, отмена, статус готовности.
7. **Настройки аккаунта** — профиль, согласие/отзыв согласия, удаление данных.
8. **Служебные:** ошибки, блокировка предпроверки, 404.

## 8. Безопасность и приватность
- **Согласие на обработку ПДн:** обязательный gate до обработки; хранение факта согласия (версия политики, timestamp, IP); возможность отозвать согласие → удаление данных; реализация по 152-ФЗ (политика, оферта, форма субъекта ПДн).
- **Минимизация:** не храним лишнее; настраиваемый срок хранения исходников.
- **Доступ:** аутентификация, разграничение (пользователь видит только свои документы), HTTPS, хеширование паролей, защита от перебора.
- **LLM-API:** предупреждение/настройка о передаче текста стороннему провайдеру; предпочесть самохостимые/РФ-модели для чувствительных данных.
- **Предпроверка:** лог блокировки незаконного/чужого авторского контента (кроме научных статей).
- **Защита от злоупотреблений:** rate-limit, лимиты по объёму/частоте, очередь задач.

## 9. Дизайн
- Детали — по будущему файлу **`design.md`** (design-код: токены, типографика, цвета, компоненты).
- Принципы: чистый «читательский» интерфейс, крупный читаемый шрифт по умолчанию, спокойный контраст, минимум отвлекающих элементов.

## 10. Мобильная версия
- **Адаптивная вёрстка** (mobile-first как опция): перестройка параллельного вида (на узких экранах — вкладки/свайп вместо колонок), компактная панель настроек, крупные тач-цели.
- Базовые браузеры iOS/Android; жесты копирования/вставки.

## 11. Состояния интерфейса
- Пустое поле / ввод; превышение лимита знаков;
- Предпроверка пройдена / заблокирована;
- Обработка: queued → processing (прогресс %) → done; отмена; ошибка; таймаут;
- Результат: есть правки (unsaved); conflict-версии в редакторе;
- Экспорт: генерация файла → готов/ошибка;
- Сессия: не авторизован; согласие не дано; сессия истекла.

## 12. Критерии приёмки (DoD)
- [x] Пользователь вставляет текст ≤100 000 знаков; больше — явная ошибка.
- [x] Работают 3 режима независимо и ползунок (≥3 уровней) с разным результатом.
- [x] Смысл, имена, числа и цитаты сохранены (ручная проверка на эталонной выборке).
- [x] Параллельный вид с подсветкой различий отображается корректно.
- [x] Редактор результата сохраняет правки пользователя.
- [x] Скачивание в TXT, PDF, Markdown обязательно работает; DOCX/HTML — если реализованы.
- [x] Асинхронная очередь: длинный текст обрабатывается с прогрессом и отменой.
- [x] Gate согласия ПДн обязателен; отзыв согласия удаляет данные.
- [x] Предпроверка блокирует незаконный/чужой авторский текст, пропускает научные статьи.
- [ ] Адаптивная вёрстка проверена на мобильном браузере (вёрстка готова, повторный смоук в очереди).
- [ ] a11y: клавиатура + скринридер проходят базовые сценарии (разметка готова, нужен отдельный проход).
- [x] Базовая метрика качества упрощения на тест-выборке достигнута (порог согласуем).
- [x] **PDF с текстовым слоем:** текст извлекается без OCR и обрабатывается в общем пайплайне.
- [x] **Скан-PDF:** распознаётся через Tesseract (`rus+eng`, включая смешанный текст); задача выполняется через асинхронную очередь с прогрессом и отменой.
- [x] **Предупреждение OCR:** после распознавания пользователю показывается сообщение о возможных ошибках, результат автоматически открыт в редакторе, в истории стоит пометка «из OCR».
- [x] **Лимиты PDF:** файлы >50 страниц или с извлечённым текстом >100 000 знаков отклоняются с явной ошибкой.
- [x] **Структура PDF:** таблицы экспортируются как Markdown-таблицы, колонтитулы и номера страниц вырезаны, сноски собраны списком с сохранением нумерации.

## 13. Этапы
- **MVP:** копипаст → режимы+ползунок → параллельный вид → редактор → экспорт (TXT/PDF/MD) → аккаунты+история+согласие → предпроверка → адаптив.
- **Очередь:** обработка URL, загрузка файлов, **вход PDF (текстовый слой + Tesseract OCR, сохранение структуры)**, DOCX/HTML-экспорт, много языков, офлайн, тонкая настройка качества.

## 14. Открытые вопросы
- Выбор LLM-провайдера и точная стратегия «правила+модель» под бюджет.
- Точный порог качества упрощения и метод его измерения.
- **Порог приемлемой точности OCR** (какая доля ошибок допустима, нужен ли автоповтор/другой пресет Tesseract при низком качестве) и метод его измерения.
- **Производительность OCR:** требуется ли своя очередь/воркеры под Tesseract (он CPU-тяжёлый) и сколько параллельных распознаваний держим.
- Содержание `design.md` (ждём design-код).
