# Челотекст

> PWA, которая делает текст легче для чтения, **не сокращая содержание**.
> Смысл, факты, имена, числа, даты и цитаты сохраняются 1:1. Это не саммаризатор.
> Состояние описано по коду на 25 ноября 2026 (сверка: [docs/HANDOFF.md](./docs/HANDOFF.md)).

**Содержание:** [доступ к GigaChat](#быстрый-старт-доступ-к-gigachat) · [запуск](#запуск) · [как пользоваться](#как-пользоваться) · [команды](#команды) · [все настройки `.env`](#настройка-через-env) · [GigaChat подробно](#gigachat-подробности) · [другие провайдеры](#другие-провайдеры) · [проверка и неполадки](#проверка-и-неполадки) · [безопасность](#безопасность) · [структура](#структура-проекта) · [деплой на VDS](#деплой-на-vds) · [ограничения](#ограничения) · [документация](#документация)

## Что это

Веб-сервис для массового читателя длинных текстов на русском. Пользователь вставляет текст (или даёт ссылку/файл), выбирает три независимых режима и глубину правки, получает результат с подсветкой различий, правит его в редакторе и скачивает в одном из пяти форматов.

- **R1** — визуальное форматирование: абзацы, заголовки, интервалы.
- **R2** — лингвистическое упрощение: канцеляризмы, длинные предложения, повторы.
- **R3** — структурирование: заголовки, списки, ключевые мысли.
- **Глубина** — ползунок 1…5, от лёгкой правки до глубокого упрощения.

Стек: **Node.js 22+**, Express, встроенный `node:sqlite`, собственная in-process очередь, `tesseract.js`, `pdfjs-dist`, PWA service worker. Python, Docker, Redis и Celery в рабочей конфигурации не используются.

## Быстрый старт: доступ к GigaChat

Рабочий `.env` **уже создан и почти полностью заполнен**: `LLM_PROVIDER=gigachat`, `LLM_ENABLED=true`, модель, адреса API и сертификат прописаны. Вам осталось вписать только доступ к API — три пустых поля.

### Шаг 1. Получите ключ в Студии Сбера

1. Откройте личный кабинет **GigaChat Studio** → проект **GigaChat API**.
2. В левой панели выберите **Настройки API** → **Получить ключ**.
3. Скопируйте **Authorization Key** **или** пару **Client ID** + **Client Secret**.
   Значения показываются **один раз** и в кабинете не хранятся; кнопка доступна ролям «Владелец» и «Администратор». Если ключ утерян — нажмите «Получить новый ключ».

### Шаг 2. Впишите ключ в `.env`

Откройте `C:\proj\chelotext\.env` и заполните **один** из двух вариантов:

```dotenv
# Вариант 1: готовый Authorization Key
GIGACHAT_CRED=<скопированный Authorization Key>
```

```dotenv
# Вариант 2: вместо GIGACHAT_CRED
GIGACHAT_CLIENT_ID=<скопированный Client ID>
GIGACHAT_CLIENT_SECRET=<скопированный Client Secret>
```

Оба варианта равнозначны: из пары сервер сам соберёт Authorization Key как `base64(client_id:client_secret)`. Остальные строки в `.env` **менять не нужно**. Если файл `.env` случайно удалён — сделайте `copy .env.example .env` (шаблон заполнен так же, пустыми остались только эти три поля).

### Шаг 3. Перезапустите сервер

`.env` читается только при старте. Остановите сервер (`Ctrl+C` в окне, где он запущен) и снова выполните `npm start`.

### Шаг 4. Убедитесь, что ключ подхватился

```powershell
curl.exe -s http://127.0.0.1:3000/healthz
```

До ввода ключа там будет `"configured": false, "credentialSource": "not configured"`; после перезапуска с ключом — `"configured": true` и `"credentialSource": "authorization key"` либо `"client id + client secret"`. Сам ключ в ответе не показывается.

Корневой сертификат НУЦ Минцифры уже лежит в `certs/russian_trusted_root_ca.crt`. Если его нет (например, вы заново склонировали проект), выполните `npm run certs` или положите файл вручную, скачав его с <https://www.gosuslugi.ru/crt>. **Проверку TLS отключать запрещено.**

> Пока ключ не заполнен, сервис работает только на движке правил: пользователь не видит ошибку, режим R2 просто не вызывает модель. Живые вызовы GigaChat требуют реального ключа.

## Запуск

Нужна Node **>= 22.5.0** (`node --version`). Зависимости ставятся обычным npm.

```bash
npm install
npm start
```

Откройте <http://127.0.0.1:3000>. Другой порт: в PowerShell `$env:PORT=3311; npm start`, в bash `PORT=3311 npm start`. Готовность сервера: `GET /healthz`.

Секрет сессий, если `SESSION_SECRET` не задан, создаётся сам в `data/.session-secret`. PWA ставится из браузера как обычное приложение; без сети доступна только оболочка (см. [Ограничения](#ограничения)).

## Как пользоваться

1. **Регистрация** → **согласие на обработку данных**. Без согласия защищённые API возвращают **403** — это нормальная защита, а не ошибка ключа.
2. На `/app` вставьте текст (или дайте ссылку/загрузите TXT/MD, DOCX, PDF) и включите нужные режимы **R1/R2/R3**; ползунок глубины **1…5** задаёт силу правки.
3. Нажмите **«Обработать»**. Короткий текст обрабатывается сразу; длинный и скан-PDF уходят в очередь с прогрессом и отменой.
4. Сравните «Было / Стало», поправьте результат в редакторе, скачайте **TXT / Markdown / HTML / PDF / DOCX**.
5. История, ревизии и настройки хранения — в `/history` и `/settings`; отзыв согласия удаляет данные.

Что важно: режим **R2** с включённой моделью отправляет чанки текста провайдеру. Для чувствительных материалов используйте `LLM_PROVIDER=rules` или self-hosted Ollama. Минимальная длина текста — 80 знаков; максимум — 100 000 знаков.

|---|---|
| `npm start` | Запуск сервера на `:3000` (`node --no-warnings server/index.js`). |

| Хранилище | `DATA_DIR=data`, `RETENTION_DAYS=30`; `DB_FILE` закомментирован — по умолчанию `data/chelotext.sqlite` |

| Rate limit | `RL_LOGIN_PER_HOUR=10`, `RL_REGISTER_PER_HOUR=5`, `RL_PROCESS_PER_HOUR=30`, `RL_UPLOAD_PER_HOUR=20`, `RL_GLOBAL_PER_MINUTE=240` |
| LLM | `LLM_PROVIDER=gigachat`, `LLM_ENABLED=true`, `LLM_MODEL=GigaChat-2`, `LLM_BASE_URL=http://127.0.0.1:11434`, `LLM_API_KEY=` (не используется), `LLM_TIMEOUT_MS=45000`, `LLM_MAX_RETRIES=2`, `LLM_MAX_TOKENS=4096`, `LLM_CHUNK_CHARS=3000`, `LLM_TEMPERATURE=0.2` |

## GigaChat подробности

- **Авторизация.** Ключ → OAuth-токен на **30 минут**; сервер кэширует токен и обновляет его за 60 сек до истечения (`GIGACHAT_TOKEN_SKEW_MS`) и один раз при `401`. Каждый запрос токена несёт новый `RqUID` (uuid4), заголовок `Authorization: Basic <ключ>` и тело `scope=GIGACHAT_API_PERS`. Запросы к модели идут с `Authorization: Bearer <токен>`.
- **Один поток.** У физлиц параллельные запросы получают `429`, поэтому вызовы сериализуются внутри процесса, а `JOB_CONCURRENCY=1`. Повторы при `429/502/503/504` — с экспоненциальной паузой. Для ИП/юрлиц поменяйте `GIGACHAT_SCOPE` на `GIGACHAT_API_B2B` или `GIGACHAT_API_CORP`.
- **Запросы к модели.** `POST https://api.giga.chat/v1/chat/completions`; одно системное сообщение первым, затем пользовательский текст; `User-Agent` обязателен. Длинный текст режется на чанки по 3000 знаков с перекрытием, таблицы и сноски сохраняются из оригинала. Ответ с `finish_reason: length` (оборванный) отвергается — блок остаётся после правил.
- **Модель.** По умолчанию `GigaChat-2` (Lite, быстрый). Доступные модели вашего ключа: `GET https://api.giga.chat/v1/models`. При смене модели поменяйте **обе** переменные — `GIGACHAT_MODEL` и `LLM_MODEL`.
- **Бесплатные токены физлицам.** Для `GigaChat-2` — 250 000 000 токенов на 12 месяцев (условия могут меняться, смотрите тарифы Сбера). Остаток — в личном кабинете; при исчерпании приходит `402`.
- **Сертификат.** Нужен корневой PEM НУЦ Минцифры. `npm run certs` сохраняет его в `certs/russian_trusted_root_ca.crt`; клиент добавляет PEM к доверенным корневым CA. Путь можно переопределить через `GIGACHAT_CA_FILE`. **Никогда не отключайте проверку TLS** (`rejectUnauthorized=false`, `verify=False`) — добавляйте сертификат.
- **Целостность.** После модели результат сверяется с исходником по числам, датам, URL, цитатам и капитализациям. При ошибке API или чанка задача не падает: включается движок правил, причина пишется в `llm.fallbackReason`, а `llm.used` остаётся `false`, если ни один чанк не прошёл модель.

Подробности — в [api/GigaChat_01_Авторизация.md](./api/GigaChat_01_Авторизация.md), [api/GigaChat_02_Генерация_ответа.md](./api/GigaChat_02_Генерация_ответа.md), [api/GigaChat_03_Ошибки.md](./api/GigaChat_03_Ошибки.md).

## Другие провайдеры

GigaChat — основной вариант для физлиц. Запасные пути:

```dotenv
# ProxyAPI — OpenAI-совместимый, платный
LLM_PROVIDER=openai
LLM_ENABLED=true
LLM_BASE_URL=https://api.proxyapi.ru
LLM_API_KEY=sk-...
LLM_MODEL=openai/gpt-5-mini
```

Адаптер сам дописывает `/v1/chat/completions`, поэтому суффикс `/v1` в `LLM_BASE_URL` **не нужен**. `sk-...` — заполнитель, а не рабочий ключ. См. [api/ProxyAPI_03_Генерация_текста.md](./api/ProxyAPI_03_Генерация_текста.md).

Self-hosted без отправки текста наружу: `LLM_PROVIDER=ollama`, `LLM_ENABLED=true`, `LLM_MODEL=qwen2.5:7b-instruct`, `LLM_BASE_URL=http://127.0.0.1:11434`.

Полностью без модели: `LLM_PROVIDER=rules`, `LLM_ENABLED=false` — текст никуда не уходит.

## Проверка и неполадки

| Симптом | Причина | Что делать |
|---|---|---|
| `/healthz` показывает `configured:false` | Ключ не вписан, вписан в `.env.example` вместо `.env`, или сервер не перезапускался | Проверьте `.env`, уберите пробелы вокруг значения, перезапустите сервер |
| `certificate verify failed: self-signed certificate in certificate chain` | Нет корневого сертификата НУЦ Минцифры | `npm run certs`, проверьте `GIGACHAT_CA_FILE`. **Не отключайте проверку TLS** |
| HTTP `400`, `scope is empty` / `scope ...` | Пустой или неподходящий `scope` | Для физлиц `GIGACHAT_SCOPE=GIGACHAT_API_PERS`; для юрлиц — B2B/CORP |
| HTTP `401`, `Can't decode 'Authorization' header` | Опечатка или лишние символы в ключе | Скопируйте Authorization Key заново в `.env`, перезапустите сервер |
| HTTP `401`, `Unauthorized` от модели | Токен старше 30 минут | Клиент обновляет токен сам; если повторяется — перевыпустите ключ в кабинете |
| HTTP `402 Payment Required` | Кончились бесплатные токены модели | Посмотрите остаток в кабинете; смените `GIGACHAT_MODEL` на модель с токенами или пополните баланс |
| HTTP `403 Unauthorized` на `api.giga.chat` | Не передан `User-Agent` | `GIGACHAT_USER_AGENT=chelotext/1.0` в `.env`. Не путайте с **403 формы**: это отсутствие согласия на ПДн |
| HTTP `404` | Неверное имя модели | Сверьте со списком `GET https://api.giga.chat/v1/models` |
| HTTP `413` / `422` | Чанк больше контекста или неверная структура сообщений | Уменьшите `LLM_CHUNK_CHARS` (например, до 2000); модель должна поддерживать заданный формат |
| HTTP `429 Too Many Requests` | Параллельные запросы к API | Оставьте `JOB_CONCURRENCY=1`; клиент повторит с паузой |
| HTTP `500 Internal Server Error` | Сбой на стороне сервиса | Повторите позже; при повторе — `gigachat@sberbank.ru` |
| Обработка возвращает **403** в интерфейсе | Не дано согласие на обработку данных | Примите согласие на странице регистрации/настроек |
| `EADDRINUSE` при старте | Порт уже занят другим экземпляром сервера | Оставьте работающий экземпляр или задайте другой `PORT` |
| В консоли Windows «кракозябры» вместо кириллицы | Кодировка консоли | Запускайте с `chcp 65001` или пишите вывод в файл и читайте его |

Если модель недоступна по любой причине, задача **не падает**: результат остаётся после правил, а причина видна в `llm.fallbackReason`. Проверять работоспособность ключа лучше на учебном тексте без персональных данных.

## Безопасность

- Секреты читаются только сервером из `.env`; в код, браузер, логи и ответы API они не попадают. `/healthz` показывает лишь **факт** наличия ключа и его источник.
- `.env`, `data/`, `certs/*.crt`, `node_modules/`, `tmp/`, `*.log` и `eval/report.md` исключены через `.gitignore`. Коммитов и пушей без вашей просьбы не делалось.
- Не пересылайте ключ в чаты, скриншоты, issue и отчёты об ошибках. При утечке перевыпустите ключ в кабинете: удаление из файла недостаточно, старый ключ может действовать ещё до 250 минут.
- При включённой модели текст уходит выбранному провайдеру. Для персональных данных используйте `rules` или self-hosted Ollama.
- Согласие на ПДн обязательно: без него API отдаёт 403, а отзыв согласия удаляет данные пользователя.

## Деплой на VDS

Готовый комплект лежит в [deploy/](./deploy/README.md): `Dockerfile`, `docker-compose.yml`, конфиг nginx, systemd-юнит, шаблон production-`.env` и скрипт `deploy.sh` с командами `install|update|status|backup`.

Коротко:

```bash
# Docker (рекомендуется): приложение на 127.0.0.1:3000, nginx с HTTPS снаружи
cp deploy/.env.production.example .env   # вписать только ключи GigaChat
./deploy/deploy.sh install

# Без Docker: Node 22 + systemd
MODE=systemd sudo -E ./deploy/deploy.sh install
```

Подробности — [deploy/README.md](./deploy/README.md): доступ к приватному репозиторию через deploy key, сертификат НУЦ Минцифры, nginx + certbot, бэкапы `data/`, обновление и диагностика.

## Ограничения

- **До ввода ключа работает только движок правил**: `.env` уже настроен на `gigachat`, но без ключей или при ошибке API задача честно падает на правила. R2 без модели — «правила + заглушка». Качество упрощения ограничено словарями и эвристиками; контроль целостности проверяет числа, даты, цитаты, ссылки и капитализации, но не семантику целиком.
- **Офлайн доступна только оболочка**: service worker кэширует статику и отдаёт страницу «Нет сети»; `/api/*` не кэшируется, обработка текста без сети невозможна (ТЗ 5, офлайн исключён из MVP).
- **OCR медленный** на слабых машинах: страница PDF рендерится через `@napi-rs/canvas`, затем распознаётся `tesseract.js`. Скан-PDF всегда уходит в асинхронную очередь; результат помечается «из OCR» и открывается в редакторе с предупреждением о возможных ошибках. Средняя уверенность ниже порога фиксируется в метаданных.
- **Лимиты**: 100 000 знаков на текст и 50 страниц PDF (что наступит раньше), файл до 25 МБ. EPUB, заявленный в ТЗ как «очередь», пока не поддерживается — принимаются TXT/MD, DOCX и PDF.
- **Очередь живёт в памяти процесса**: после перезапуска задачи в `processing` помечаются `failed` (`interrupted`), а не перезапускаются; внешнего брокера нет.
- **Визуальный нюанс правил**: сокращение «г.» в начале абзаца может стать «Г.»; в проверке целостности даты нормализуются к нижнему регистру, но сама правка регистра остаётся видимой.
- **Один поток GigaChat** для физлиц: внутри процесса запросы сериализуются; при нескольких процессах каждый имеет свою очередь, поэтому параллелизм задач ограничен `JOB_CONCURRENCY=1`.
